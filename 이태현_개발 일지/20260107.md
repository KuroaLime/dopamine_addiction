## 작업 상세
### 1) 세션 구조 만들기
- 목적: 클라이언트 1명 연결에 필요한 상태를 “세션 1개”로 묶어서 관리
- 현재 세션이 들고 있어야 하는 핵심
  - `SOCKET` (클라 소켓)
  - `OVERLAPPED`(또는 I/O 컨텍스트 구조체) + `WSABUF`
  - recv 버퍼(수신 누적의 기반)
- 포인트
  - IOCP의 `CompletionKey`로 `Session*`를 넘겨서, 워커 스레드에서 “누구의 완료 통지인지” 바로 찾게 함

### 2) Accept 이후 IOCP에 소켓 연결
- 흐름(현재 단계 기준)
  1. `accept()`로 `clientSock` 얻기
  2. `Session` 생성 + `clientSock` 저장
  3. `CreateIoCompletionPort((HANDLE)clientSock, hIocp, (ULONG_PTR)sessionPtr, 0)` 로 IOCP에 등록
  4. `WSARecv`(또는 PostRecv 함수)로 “최초 수신” 비동기 요청 걸기
- 체크 포인트
  - `WSARecv`가 `SOCKET_ERROR`여도 `WSAGetLastError()==WSA_IO_PENDING`이면 정상(비동기 진행)
  - 지금 구조에서는 `listenSock`은 굳이 IOCP에 안 붙이고, `clientSock`만 붙여도 됨(accept는 동기 처리)

### 3) 워커 스레드 완료 통지 루프 처리
- 워커 스레드 루프 핵심
  - `GetQueuedCompletionStatus(hIocp, &bytes, &key, &ov, INFINITE)`
  - `key` → `Session*`로 캐스팅해서 대상 세션 확보
  - `bytes == 0`이면 disconnect 가능성 높음 → 세션 정리 경로로 이동
  - 완료 통지 처리 후 다음 I/O를 다시 걸어줌(특히 Recv는 계속 재포스팅)

## 현재 상태
- “접속 → 세션 생성 → IOCP 등록 → (Recv 요청) → 워커에서 완료 통지 받는 루프”까지 뼈대 구축 완료
- 아직 로비 로직/패킷 처리/Send 큐/정리(Disconnect) 등은 미구현
