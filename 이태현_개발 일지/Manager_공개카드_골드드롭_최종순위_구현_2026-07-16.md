# Manager 공개 카드·골드 드롭·최종 순위 구현

작성일: 2026-07-16

## 1. 요구사항 해석

1. 카드 게임 진입 시 각 플레이어가 보유 카드 3장 중 공개할 1장을 선택한다.
2. 선택하지 않은 2장이 실제 섯다 패가 된다.
3. 모든 플레이어가 공개 카드를 확정한 뒤 기존 베팅과 판정 로직을 진행한다.
4. 배틀 로얄에서 수동으로 버린 카드는 버린 플레이어의 위치에 같은 카드로 생성한다.
5. 플레이어 사망 시 카드는 유지하고 일정량의 골드를 월드에 드롭한다.
6. 경기 종료 순위는 현재 보유 골드가 많은 순서이며 사망으로 잃은 골드는 그대로 손해가 된다.

## 2. 서버 권위 데이터 경계

### 비공개 데이터

`AMainPlayerState::OwnedCards`는 `COND_OwnerOnly` 복제를 유지한다. 서버와 소유 클라이언트만 카드 3장 전체를 알 수 있다.

### 공개 데이터

`AMainPlayerState::RevealedCard`를 별도로 추가하고 일반 복제한다. 상대 클라이언트는 이 구조체의 `CardInstanceId`와 `CardID`만 확인한다.

이 분리는 공개 카드 구현을 위해 `OwnedCards` 전체를 공개하는 실수를 방지한다.

## 3. 공개 카드 선택 처리

기존 RPC `Server_SubmitSeotdaSelection(bool, bool, bool)`는 연결 호환을 위해 유지하되 의미를 변경했다.

- 기존: `true`인 카드 2장을 섯다 패로 선택
- 변경: `true`인 카드 1장을 공개 카드로 선택
- 나머지 2장: 서버가 자동으로 숨은 섯다 패로 구성

서버 처리 순서는 다음과 같다.

1. 카드 게임 단계인지 검증
2. 플레이어가 정확히 3장을 보유하는지 검증
3. 선택 플래그가 정확히 1개인지 검증
4. 카드 3장 각각의 서버 레코드, 소유자, 카드 ID가 일치하는지 검증
5. 공개 카드 1장과 숨은 패 2장으로 분리
6. 숨은 패 2장을 기존 `FSeotdaRuleService`로 평가
7. 공개 카드를 `PlayerState`에 설정
8. 제출 상태를 저장하고 전체 플레이어 제출 여부 확인
9. 전원이 제출했을 때만 기존 베팅 시작

재경기 규칙은 공개 카드를 유지하고 숨은 패 2장만 다시 지급한다.

## 4. 배틀 로얄 수동 카드 드롭

배틀 드롭은 새 카드 인스턴스를 만들지 않는다.

1. 현재 소유권과 서버 카드 레코드 검증
2. 플레이어 위치에서 아래 방향 지면 trace
3. 동일 `CardInstanceId`와 `CardID`로 `ACardDropActor` 생성
4. 생성 성공 후 보유 목록에서 제거
5. 서버 레코드를 `Owned`에서 `WorldDrop`으로 전환
6. 기존 카드 픽업 검증과 거리 제한으로 재획득 처리

지면 탐색은 NavMesh를 사용하지 않으므로 특정 섬의 NavMesh 생성 상태와 무관하다. 스폰 실패 시 카드는 플레이어 소유로 남는다.

## 5. 사망 골드 드롭

신규 `AGoldDropActor`는 서버 복제 액터다.

- 기존 `UCardGameService::DropOwnedCardsFromPlayer` 공개 함수는 제거해 사망 카드 드롭 경로를 없앴다.
- 기본 드롭량: 1000
- 실제 드롭량: `min(현재 골드, 설정 드롭량)`
- 스폰 성공 후 사망자 골드 차감
- 살아 있는 플레이어만 획득 가능
- 원래 소유자는 짧은 획득 잠금이 적용되며, 사망 상태에서는 획득 불가
- 획득 시 `AMainPlayerState::AddGold` 호출 후 액터 제거

`AddGold`는 결과를 0 이상 `MAX_int32` 이하로 제한한다.

## 6. 최종 순위

최종 점수는 경기 종료 시 `HoldingGold`다. 별도의 총 획득량을 사용하지 않으므로 다음 항목이 모두 순위에 반영된다.

- 카드 게임 베팅 지출과 상금
- 상점 구매 지출
- 사망 시 골드 손실
- 다른 플레이어가 떨어뜨린 골드 획득

정렬은 골드 내림차순, 이름 오름차순 보조 정렬이다. 같은 골드는 공동 순위로 표시한다. 재접속 유예 스냅샷에 남아 있는 플레이어도 이름과 골드가 보존되어 순위에 포함된다.

## 7. 설정값

`AMainGameMode`에서 다음 값을 조정할 수 있다.

- `GoldDropActorClass`
- `DeathGoldDropAmount` 기본 1000
- `DeathGoldSourcePickupLockSeconds` 기본 1.5초
- `DeathGoldGroundOffsetZ` 기본 45
- `DeathGoldGroundTraceDepth` 기본 2000

## 8. 검증 로그

정상 동작 시 핵심 로그는 다음과 같다.

```text
[DS] Seotda RevealOK Player=... Public=[...] Hand=[...] Combo=...
[DS] CardDiscard ... Context=BattleRoyale WorldDrop=1 Location=...
[DS] GoldDrop Spawned Player=... Amount=1000 Gold=...->...
[DS] GoldDrop Collected Player=... Amount=1000 Location=...
[DS] GameEnd ... Winner=... MoneySummary=#1 ... | #2 ...
```

실패 시에는 공개 카드 소유권 불일치, 카드 스폰 실패, 골드 스폰 실패가 Error 또는 Security Warning으로 남는다.

## 9. 남은 검증

소스 수정과 정적 검증까지만 수행한다. 사용자가 Editor/Client/Server를 빌드한 뒤 로컬 2클라이언트 및 실제 2PC 환경에서 공개 정보 범위, 카드 드롭 위치, 골드 획득, 최종 순위를 확인해야 한다.
