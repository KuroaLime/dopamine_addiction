## 작업 상세

### 1) 증상: 재부팅 후 X: 드라이브가 사라짐
- 재부팅 전에는 `subst`로 X:가 잡혀 있었음
- 재부팅 후:
  - 파일 탐색기에서 X:가 안 보임
  - CMD에서 `subst` 입력해도 목록이 비어 있음
- 결론: `subst` 매핑은 **영구가 아니라 재부팅하면 초기화**됨

### 2) 해결 방향: 로그인/부팅 시 자동으로 `subst` 실행되게 만들기
- 목표: 매번 수동으로 `subst X: ...` 치지 않게 자동화
- 시도: 작업 스케줄러(Task Scheduler)로 트리거 설정
  - 문제: 작업 위치/검색/정렬이 불편했고,
  - 실행해도 기대한 방식으로 동작하지 않거나 결과가 불확실했음
- 결론: 작업 스케줄러 방식은 잠시 보류하고 **배치 파일 기반**으로 전환

### 3) 배치(.bat)로 자동 매핑 시도 중 발생한 문제
- 배치 실행 시 에러:
  - `[FAIL] Target path not found: C:\Users\mdk73\OneDrive\臾몄꽌\GitHub\Project-for-Graduation`
- 관찰:
  - `문서`가 `臾몄꽌`처럼 깨져 보임 → **인코딩/문자셋 문제**
  - 배치 파일 첫 줄이 `癤?echo off`처럼 출력됨 → 파일이 UTF-8 BOM 등으로 저장되어 깨진 상태

### 4) 해결: 배치 파일 인코딩 문제 수정 + 경로 정상 인식 확인
- 조치(핵심):
  - 배치 파일을 **ANSI 또는 UTF-8(=BOM 없이)**로 다시 저장
  - 경로 문자열이 `문서`로 정상 표시되도록 수정
- 추가 대응:
  - OneDrive 동기화/지연 때문에 경로가 바로 안 잡힐 수 있어
    - 일정 시간 대기 후 폴더 존재 확인 로직(루프/timeout) 포함

### 5) 결과 확인
- 배치 파일 실행 후:
  - X: 드라이브가 생성됨(파일 탐색기에서도 확인)
  - 프로젝트 경로가 정상적으로 매핑됨
  - UE 프로젝트 실행 시 경로 문제로 인한 모듈 rebuild 오류 위험을 줄임
