# Manager 섯다 공개 카드 즉시 표시 수정

## 확인된 직접 원인

공개 카드 요청 경로 자체는 정상적이었다.

1. `RevealSeotdaCard()`가 한 장을 검증한다.
2. 서버 `PlayerState::RevealedCard`와 `bRevealConfirmed`를 즉시 갱신한다.
3. 같은 함수 안에서 `BroadcastSeotdaState()`도 즉시 호출한다.

문제는 브로드캐스트가 좌석 자료를 만들 때 `SeotdaTurnOrder`만 순회한 점이다. 이 배열은 모든 플레이어가 최종 패 두 장을 제출한 뒤 `StartSeotdaBettingRound()`에서 처음 채워진다. 따라서 공개 카드 단계에는 상대 좌석 payload가 비어 있었고, 최종 제출 뒤 베팅 순서가 만들어진 다음 상태 브로드캐스트에서야 공개 카드가 화면에 나타났다.

## 수정 내용

- `BroadcastSeotdaState()`가 기존 베팅 순서를 우선 보존한다.
- 이어서 현재 접속한 모든 `AMainPlayerState`를 중복 없이 좌석 목록에 추가한다.
- 공개 단계에도 각 클라이언트가 자기 자신을 제외한 모든 참가자의 `bHasRevealedCard`와 `RevealedCardID`를 즉시 받는다.
- 베팅 시작 전에는 현재 턴 플레이어를 `nullptr`로 처리해 공개 선택 단계에 잘못된 턴 강조가 나오지 않게 했다.
- `OwnedCards`는 payload에 넣지 않는다. 상대에게 전달되는 정보는 기존과 동일하게 공개 확정된 카드 ID뿐이다.

## 기대 동작

1. 플레이어 A가 공개 카드 한 장을 선택해 제출한다.
2. 서버 승인 직후 A와 다른 모든 클라이언트가 A의 공개 카드를 본다.
3. 플레이어 B가 공개하면 같은 방식으로 B의 카드도 즉시 추가된다.
4. 최종 섯다 패 두 장 제출은 공개 카드 표시와 무관하며, 베팅 시작 조건으로만 남는다.

## 런타임 확인 항목

- 공개 직후 서버에 `Seotda RevealOK`가 기록되는지 확인한다.
- 최종 두 장을 제출하기 전에 양쪽 화면에 공개 카드가 나타나는지 확인한다.
- 공개 카드만 보이고 나머지 보유 카드와 최종 패는 상대에게 노출되지 않는지 확인한다.
- 최종 제출 뒤에도 좌석과 공개 카드가 다른 자리로 이동하지 않는지 확인한다.

이 작업에서는 빌드를 실행하지 않았다.
