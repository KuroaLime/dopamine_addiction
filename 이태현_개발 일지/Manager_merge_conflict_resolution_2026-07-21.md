# Manager merge conflict 기능별 분석 및 해결 기준

작성일: 2026-07-21

충돌의 현재 버전은 `HEAD`, 친구 버전은 `a9a852be7009f51137d60100157839541327db02`로 표기되었다. 사용자의 지시에 따라 상점 동작은 친구 버전을 기준으로 해결한다.

## 1. Ability_Fire.h: 클라이언트 발사 상태의 소유 위치

- HEAD: `UAbility_Fire` 객체가 클라이언트 발사 타이머, 현재 캐릭터, 연사 속도와 연사 여부를 멤버로 보관한다.
- 친구: 클라이언트 발사 상태를 어빌리티에 보관하지 않고 캐릭터별 `UWeaponComponent`에 보관한다.
- 해결: 친구 버전을 사용한다. 클라이언트 호출이 CDO를 공유하는 구조에서 어빌리티 멤버를 쓰면 플레이어 간 상태가 섞일 수 있기 때문이다. 사용하지 않게 된 클라이언트 타이머 함수 선언도 제거한다.

## 2. Ability_Fire.cpp: 발사 예측과 타이머

### 충돌 1: include와 공통 상수

- HEAD: 서버 권위 발사 검증용 `MainGameMode`와 최소 발사/재시도 간격 상수.
- 친구: 조준점 갱신용 `UIHandler`, `TpsPlayerMainHUD`.
- 해결: 서로 다른 의존성이므로 모두 유지한다.

### 충돌 2: 발사 시작 상태

- HEAD: 어빌리티 멤버에 현재 캐릭터·발사 속도·연사 상태를 저장한다.
- 친구: `WeaponComponent`에 발사 상태와 마지막 발사 시각을 저장하고 약한 포인터를 만든다.
- 해결: 친구 버전.

### 충돌 3: 정상 연사 타이머

- HEAD: 어빌리티 자신의 타이머 핸들과 멤버 함수를 반복 호출한다.
- 친구: 무기 컴포넌트의 타이머 핸들과 약한 포인터 람다를 사용한다.
- 해결: 친구 버전.

### 충돌 4: 쿨다운 대기 후 자동 발사

- HEAD: 어빌리티 멤버 타이머로 재검사한다.
- 친구: 무기별 재시도 타이머를 사용하고 캐릭터/무기가 사라지면 정리한다.
- 해결: 친구 버전.

### 충돌 5: 발사 취소 및 정리

- HEAD: 어빌리티 멤버 타이머와 상태를 초기화한다.
- 친구: 현재 장착 무기의 두 타이머, 발사 상태, 연사 횟수와 블룸을 초기화한다.
- 해결: 친구 버전. 서버 발사 타이머와 `MainGameMode::IsBattleRoyalePhase()` 권위 검증은 충돌 밖의 HEAD 기능으로 그대로 보존한다.

## 3. MainGameMode.h: 상점 검사와 골드 드롭 API

- HEAD: `IsShopRequestAllowed()`와 `DropGoldFromPlayer()`.
- 친구: `IsPreBattleShopPhase()`.
- 해결: 골드 드롭은 상점과 무관하므로 보존한다. 친구의 상점 판정 API를 추가하고 실제 상점 RPC는 친구 API를 사용한다. 기존 API도 정의 일관성을 위해 남기되 활성 상점 경로에서는 사용하지 않는다.

## 4. MainGameMode.cpp

### 충돌 1: 카드 배치 완료 후 상점 시작

- HEAD: 복구 watchdog을 종료하고 `StartPreBattleShopPhase()` 래퍼를 호출한다.
- 친구: PreBattleShop 타이머, `ShopAvailable`, 상점 배리어를 직접 켠다.
- 해결: 친구 상점 시작 로직을 사용하고, 상점과 무관한 watchdog 완료 처리는 보존한다.

### 충돌 2: 카드게임에서 배틀로얄로 복귀

- HEAD: 연결이 끊긴 플레이어의 라운드 카드를 정리한다.
- 친구: 플레이어를 스폰 지점으로 재배치한다.
- 해결: 서로 다른 필수 작업이므로 카드 정리 후 재배치를 모두 수행한다.

### 충돌 3: 재배치 구현과 골드 기능

- HEAD: 죽음 골드 드롭 정리와 최종 골드 순위 함수가 추가되었다.
- 친구: `RedeployToSpawnPoint()`의 나머지 구현이 추가되었다.
- 해결: 친구 재배치 함수 본문을 먼저 완성해 닫고, 그 뒤 HEAD의 골드 정리·순위 함수를 배치한다. 한쪽만 고르면 함수가 잘리거나 골드 승리 조건이 사라진다.

### 충돌 4: 상점 시간 종료

- HEAD: `FinishPreBattleShopPhase()` 래퍼.
- 친구: `ShopAvailable`과 배리어를 끄고 BattleRoyale 타이머를 시작한다.
- 해결: 친구 버전.

## 5. MainPlayerController.cpp: 상점 RPC 4곳

### 충돌 1: 상점 UI 진입 요청

- `Server_PushMode`가 현재 상점 시간인지 확인하는 함수 이름과 조건의 충돌.
- 해결: 친구의 `IsPreBattleShopPhase()`.

### 충돌 2: 랜덤 업그레이드 후보 요청

- 상점 요청 가능 여부를 검사하는 함수의 충돌.
- 해결: 친구의 `IsPreBattleShopPhase()`. RPC 속도 제한과 생존·중복 요청 검사는 유지한다.

### 충돌 3: 랜덤 업그레이드 선택

- 선택 적용 전 상점 시간 검사의 충돌.
- 해결: 친구의 `IsPreBattleShopPhase()`. 인덱스·라운드·옵션 검증은 유지한다.

### 충돌 4: 고정 능력치 업그레이드 선택

- HEAD: 함수 본문과 RPC 속도 제한을 추가했다.
- 친구: PreBattleShop 단계 검사를 추가했다.
- 해결: 함수 본문과 속도 제한을 유지하고, 활성 상점 조건만 친구의 `IsPreBattleShopPhase()`로 변경한다. 둘 중 한쪽만 선택하면 함수 선언이 잘리거나 서버 호출 제한이 사라진다.

### 충돌 외 연계 조건: 상점에서 카드 버리기

- `Server_RequestDiscardCard()`도 상점 허용 여부를 기존 `IsShopRequestAllowed()`로 검사하고 있다.
- 해결: 상점 동작을 친구 버전으로 통일하기 위해 이 조건도 `IsPreBattleShopPhase()`로 변경한다. 배틀로얄 중 카드 버리기 조건은 그대로 유지한다.
