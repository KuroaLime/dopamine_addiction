## 작업 상세
### 1) 패킷 경계 처리 (Framing)
- 문제:
  - TCP는 메시지 단위가 아니라 스트림이라서, recv 한 번에 “패킷 1개”가 온다는 보장이 없음
  - 패킷이 중간에 잘리거나(Partial), 여러 개가 한 번에 붙어서(Coalescing) 들어올 수 있음
- 처리 방향:
  - 수신 데이터를 세션의 누적 버퍼에 계속 쌓아두고
  - “헤더(길이)” 기준으로 완전한 패킷만 꺼내서 처리
  - 남은 찌꺼기(미완성 패킷)는 버퍼에 남겨 다음 recv에서 이어 붙임

### 2) Send 경로 추가 (송신 흐름 정리)
- 목표:
  - 서버 로직은 “보낼 데이터 생성”까지만 하고, 실제 송신은 일관된 경로로 처리되게 만들기
- 핵심 포인트:
  - WSASend는 비동기이므로, in-flight 상태에서 버퍼가 덮어씌워지면 데이터가 깨질 수 있음
  - 그래서 “보낼 데이터 보관(큐/버퍼)” + “송신 post(WSASend)” 흐름을 분리해서 안정화
- 기대 효과:
  - 송신 순서/버퍼 안정성 확보
  - 이후 로비 브로드캐스트(전체 전송) 같은 기능 확장 기반 마련

### 3) Disconnect & 에러 처리 강화
- 처리 케이스 정리:
  - bytes == 0: 상대가 연결 종료한 것으로 보고 세션 종료 플로우 진입
  - GetQueuedCompletionStatus 실패: 에러 상황으로 판단하고 안전하게 정리 루틴 수행
  - shutdown(SD_BOTH) 후, 진행 중 IO가 끝나면 소켓 close 및 세션 delete 되도록 정리 순서 강화
- 목적:
  - “끊김/에러”가 나도 서버가 뻗지 않고 세션이 깔끔하게 정리되게 만들기
