## 작업 상세

### 1) 세션별 SendQueue + sendInFlight
- 목적: 동시 송신 요청이 와도 버퍼 덮어쓰기/경합 없이 “순서대로” 보내기
- 구현:
  - ClientContext에 `sendQueue`, `sendInFlight`, `sendLock(SRWLOCK)` 추가
  - `QueueSendPacket()`에서
    - inFlight가 false면 즉시 송신 시작
    - true면 큐에 적재
  - 송신 완료 후 `KickNextSendIfAny()`로 다음 패킷 송신

### 2) Partial Send 처리
- 목적: WSASend 완료 바이트가 전체 길이보다 작을 때(부분 전송) 남은 데이터를 이어 보내기
- 구현:
  - PerIoContext에 `dynBuffer`, `dynOffset`, `dynTotal` 추가
  - SEND 완료 시:
    - `dynOffset += bytes`
    - 남은 바이트가 있으면 `PostSendInternal()`로 재전송
    - 모두 보내면 io 해제 후 다음 큐 송신 시작

### 3) PacketHeader + 패킷 경계 처리 + Dispatcher 뼈대
- 목적: TCP 스트림에서 패킷 단위 분리(Sticky/Fragment 해결)
- 구현:
  - ClientContext에 `streamBuf` 추가
  - RECV 완료 시 `AppendAndProcess()`로 streamBuf에 누적
  - `ProcessStreamBuffer()`에서:
    - 헤더(4B) 확인 → size/type 파싱(ntohs)
    - size 유효성 검사
    - 패킷이 다 모였을 때만 Dispatch 호출
  - `DispatchPacket()`에서:
    - C2S_PING 수신 시 S2C_PONG 응답

## 남은 이슈/체크 포인트
- 현재 `streamBuf.erase(begin, begin+pktSize)`는 비용이 큼(나중에 링버퍼/offset 방식으로 개선 고려)
- BeginClose 타이밍에서 outstanding IO / sendQueue 정리 흐름이 레이스 없는지 추후 테스트 필요
- 지금은 accept() 루프 방식(추후 AcceptEx로 확장 가능)
