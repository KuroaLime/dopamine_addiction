## 1) 배경 / 목표
- 배경: 지난 작업에서 방 목록 수신이 가능해졌으므로, 실제 방에 들어가고 나가는 상호작용이 필요함
- 목표:
  - (1) 클라이언트의 방 입장 요청 처리 및 검증
  - (2) 인원 기반 방 상태(대기/게임중) 자동 관리
  - (3) 변화 발생 시 로비에 있는 모든 사용자에게 즉시 동기화(푸시)

---

## 2) 작업 상세

### 2-1. 방 입장 로직 및 예외 처리 (HandleRoomJoinReq)
- 기능: 클라이언트가 보낸 `roomId`를 확인하여 방 멤버 리스트에 추가함
- 예외 처리(거절 메시지):
  - INVALID_ROOM: 존재하지 않는 방 ID 요청 시
  - FULL: 방 인원이 이미 최대치(`ROOM_MAX_PLAYERS`, 4명)일 때
  - IN_GAME: 방이 이미 게임 시작 상태일 때
- 결과 통보: `S2C_ROOM_JOIN_RES` 패킷에 결과 코드(`RoomResult`)와 입장 성공 시 방 정보를 담아 응답

### 2-2. 방 상태 자동 전이
- WAITING → IN_GAME: 입장 후 방 인원이 4명이 되면 상태를 자동으로 `IN_GAME`으로 변경
- IN_GAME → WAITING: 퇴장/접속종료로 인원이 4명 미만이 되면 다시 대기 상태로 복구

### 2-3. 실시간 방 상태 동기화 (BroadcastRoomList)
- 방식: 서버 사이드 푸시(Push) 개념 적용
- 트리거: 방 상태에 변화를 주는 모든 이벤트 발생 시 호출
  - 클라이언트가 방에 정상적으로 입장했을 때
  - 클라이언트가 명시적으로 방에서 나갔을 때(`HandleRoomLeaveReq`)
  - 클라이언트의 연결이 비정상적으로 끊겼을 때(`OnClientDisconnected`)
- 내용: 현재 접속 중인 모든 세션(`m_sessionByCtx`)을 순회하며 최신 방 목록(`S2C_ROOM_LIST_RES`)을 강제로 재전송함
