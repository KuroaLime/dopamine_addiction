## 4. 아키텍처 핵심 패턴

### 4.1 페이즈 전략 패턴 (게임 흐름)
- **AMainGameMode = Context**: 페이즈 머신(`EDediServerPhase`: Ready→BattleRoyale→TransitionToCard→CardGame→Result→...)과 매치 상태를 소유.
- **전략(UPhaseStrategy 파생)**: `UTPSPhaseStrategy` / `UCardPhaseStrategy` 가 페이즈별 셋업(`OnPhaseStart`)·정리(`OnPhaseEnd`)를 대칭으로 소유.
- 전략은 `friend` 없이 **public Context API + Phase 인터페이스 6종**으로만 GameMode/GameState/PC를 조작 → 결합도 최소화.

### 4.2 도메인 서비스 분리
- `FSeotdaRuleService` — 섯다 규칙(광땡/땡/구사/암행어사 등) **순수 함수**, 상태 없음 → 단위 테스트 용이.
- `FCardPlacementService` — 카드 배치(nav/geometry), 설정 주입형.
- `UCardGameService` — 카드게임 도메인 **상태 + 로직**(UObject), GameMode가 위임.

### 4.3 자체 제작 GAS
- `PFGASC`(어빌리티 시스템 컴포넌트) 중심으로 모든 캐릭터 행동을 어빌리티화.
- 이동/카메라는 직접 처리(어빌리티 대상 아님), 카드 베팅/선택은 턴제 규칙이라 PC RPC 사용.

### 4.4 복제 모델
- 서비스는 **서버 전용**. 클라 전파는 PlayerState / GameState 복제 + PlayerController RPC로 수행.
