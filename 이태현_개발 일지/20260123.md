## 작업 상세
### 1) 접속 처리: 세션ID 부여 + S2C_WELCOME
- 목적: 클라이언트가 “내가 누구인지(세션 식별자)”를 서버로부터 확정적으로 받도록 함.
- 내용:
  - accept 후 서버에서 세션ID 생성/부여
  - 해당 세션ID를 S2C_WELCOME으로 클라에 1회 전송

### 2) 접속 시 방 목록 자동 전송: S2C_ROOM_LIST_RES
- 목적: 접속 즉시 “현재 방 상황”을 클라가 바로 볼 수 있도록 함.
- 내용:
  - 접속 완료 직후 서버가 방 목록을 S2C_ROOM_LIST_RES로 전송
  - 방 목록에는 (예: 방ID / 현재 인원 / 상태(대기/게임중) / 최대 인원(4) 등) 방 요약 정보가 들어가도록 설계

### 3) 방 목록 재요청 처리: C2S_ROOM_LIST_REQ → S2C_ROOM_LIST_RES
- 목적: UI에서 새로고침/갱신 버튼 등으로 방 목록을 다시 받을 수 있게 함.
- 내용:
  - 클라가 C2S_ROOM_LIST_REQ를 보내면
  - 서버는 최신 방 목록으로 S2C_ROOM_LIST_RES 응답

### 4) 구조 분리: LobbyService.* 도입
- 목적: 네트워크 기반(ServerMain)과 로비 규칙(방/목록/세션 정책)을 분리해서 충돌/의존을 줄임.
- 역할 구분:
  - ServerMain: accept/recv/send, 패킷 수신 후 “로비 서비스 호출”까지 담당
  - LobbyService: 세션 등록/관리, 방 목록 생성/응답 로직 담당
